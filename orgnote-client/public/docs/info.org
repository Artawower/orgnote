* [#A] OrgNote
[[https://github.com/Artawower/orgnote][OrgNote]] is a knowledge management system built around [[https://www.orgroam.com/][Org-roam]], a GNU Emacs package for organizing and linking notes.
/This is a beta version: it may contain bugs and could be unstable. Please report any issues you encounter./

* [#B] Manifesto
The project's goal is to provide a full-featured Org-roam experience across desktop, mobile, and web (+PWA).

- The project is free for everyone /except for some premium features that require server resources/.
- This is an open-source project: anyone can contribute and inspect the codebase.
- The project is community-oriented. If you have ideas, please share them.
  /Patrons can vote on feature priorities./
- Premium features are free for open-source developers.
  /Distribution is limited, but I'll do my best to accommodate./
- No personal data collection and no trackers.

* [#C] Limitations
*Back up your data regularly.*

- There is currently no support for [[https://en.wikipedia.org/wiki/Conflict-free_replicated_data_type][CRDT]]. This means that synchronization via =orgnote-cli= may result in data conflicts.
  (Automatic backups are created if you use [[https://github.com/Artawower/orgnote.el][orgnote.el]] in Emacs.)
- Database migrations are not yet implemented. I'm focusing on core features first.
  This means that after updates, your data may not be automatically migrated.
- The org-mode parser is custom-built and doesn't support all org-mode constructs yet.
  If you encounter parsing bugs, please report them: [[https://github.com/Artawower/orgnote/issues][orgnote/issues]].
- The UI design is evolving. Contributions from designers are welcome!
- The iOS version is not published yet. It will be released when we raise enough for Apple Developer Program fees via [[https://www.patreon.com/artawower][Patreon]] (~$120/year).
  /You can use the *PWA* version on Apple devices right now./

* [#D] Plans
I have many ideas for integrating org-mode into a mobile app. Some features require significant time and resources; others are part of a longer-term vision.

The ideal app should include:

- Programmable configuration
- Linking and executing =src= code blocks
- Extension support
- CRDT support for seamless synchronization
- Full support for org-mode constructs
- Mobile notifications for your agenda
- Integration with third-party tools
